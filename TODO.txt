HAPPENED
  The shell and the Overview took six build and review rounds. The reviews
  were worth it: they found that a count could be silently cut at a width
  where the screen looked fine, that the tab bar could be cut in half, and
  that the title line could read "coding-lane".
  Three mistakes of the orchestrator, all of them committed into history: git
  add -A swept a builder's uncommitted work into a docs commit before it was
  reviewed; a kickoff prompt was left sitting in an input box because enter
  arrived before the text finished typing; and a steer sent to a running agent
  was never submitted, so the correction sat unread in the input box. All
  three are now rules in the skill: stage by name; send the whole kickoff as
  one call, wait a second, send enter, then read the pane to confirm the text
  left the box; and a steer follows the same sequence.
  The reviewers ran pty sweeps over every terminal size, which is how the
  width-dependent defects were found, and which cost about fifty minutes a
  round. From now on a reviewer runs the gate and reads the code. A harness
  worth keeping becomes a unit of its own.

  deviations and a sync script. Still open: which fields are rendered as
  markdown and which are escaped.
  The panes now run the regular opencode, not mini: herdr's opencode
  integration reports the agent's own state, so herdr agent wait --until idle
  is the wake signal and a stall is visible. The panes start with
  OPENCODE_CONFIG=flow/builder.json or flow/reviewer.json and --standalone, so
  the role config is read. The models are the aliases tuned-builder and
  tuned-review in the global opencode config: the same upstream model, one
  variant each, because a model with several variants does not carry the
  selected effort into the TUI.
  The builders may add or edit the mock data when a finding needs data the
  fixtures do not have - through mock-data/generate.py, and the generator must
  keep reproducing the committed tree byte for byte.
  The store is discovered twice, with two rules that disagree: raul walks the
  ancestors itself and stops at the first coding-lanes/work folder, while
  core stops at the first coding-lanes folder whether or not work is inside
  it. One rule belongs in core, next to the store it defines: a function that
  finds the work folder of the nearest project. Should be closed before talita
  lands, since the two tools would then disagree about the same project.
  crates/core: Claim::lease_expired compares timestamps as strings, and a
  lease written without seconds looks live for up to a minute. Reported in
  every review round since the first and never fixed, because core was out
  of scope for the raul rounds. Its own unit.
  The journal: activity.json exists in the model but its event kinds are not

  A render mode for raul: raul --render --plain prints the current screen as
  text and exits. It is how a prototype is captured and how a snapshot test is

  made its prototypes honest: captured output, not a drawing.

    the order is policy and sits on top, the queue is progress under it, the
