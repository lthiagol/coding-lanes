HAPPENED
  The shell and the Overview took six build and review rounds. The reviews
  were worth it: they found that a count could be silently cut at a width
  where the screen looked fine, that the tab bar could be cut in half, and
  that the title line could read "coding-lane".
  Two mistakes of the orchestrator, both committed into history and both
  repeated once: git add -A swept a builder's uncommitted work into a docs
  commit before it was reviewed, and a kickoff prompt was left sitting in an
  input box because enter arrived before the text finished typing. The second
  is now a rule in the skill: send the whole kickoff as one call, wait a
  second, send enter, then read the pane to confirm the text left the box.
  The first is now a rule too: stage by name.
  The reviewers ran pty sweeps over every terminal size, which is how the
  width-dependent defects were found, and which cost about fifty minutes a
  round. From now on a reviewer runs the gate and reads the code. A harness
  worth keeping becomes a unit of its own.

  deviations and a sync script. Still open: which fields are rendered as
  markdown and which are escaped.
  crates/core: Claim::lease_expired compares timestamps as strings, and a
  lease written without seconds looks live for up to a minute. Reported in
  every review round since the first and never fixed, because core was out
  of scope for the raul rounds. Its own unit.
  The journal: activity.json exists in the model but its event kinds are not
  defined, so the Overview has no activity block and there is no Activity tab.
  The autopilot: the orchestrator role has no job yet.
  A render mode for raul: raul --render --plain prints the current screen as
  text and exits. It is how a prototype is captured and how a snapshot test is
  written. maitre does the same with maitre --render --plain, and it is what
  made its prototypes honest: captured output, not a drawing.
  The Autopilot tab is the only raul tab whose design is not settled. Pilot it
  the way maitre did its layout: two or three variants in terminal text, the
  winner built, the rest kept as the record of what was compared. The ideas
  worth carrying over from maitre's Sous-Chef tab:
    the order is policy and sits on top, the queue is progress under it, the
    stamp at the foot says whether the automation runs - policy above,
    progress below, and the same fact never twice;
    the agent count is a composition, not a number: three agents means one per
    role, two means the orchestrator reviews, one means the human reviews,
    because an agent cannot review itself;
    the stamp prints no number it cannot compute;
    the order lives on the tool's side, not in the project's data;
    the crew is runtime state, and only the runtime has it.
  A pty harness in the repo, scripts/pty-sweep.py, and snapshot tests of the
  rendered screens. The render mode above is the first half of this.
  talita's own verbs. Out of scope, and it stays out of scope until it is
  asked for explicitly. Do not start it because the other tabs are done.
