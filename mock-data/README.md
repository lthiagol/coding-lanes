# mock-data

Mocked task data — tasks across every lifecycle stage, plus edge cases. Text is
lorem ipsum; the shape is what matters.

Generated by [`generate.py`](generate.py):

```sh
python3 mock-data/generate.py
```

The folder mirrors a managed project's data folder, so it can be copied into a
project as-is.

```
mock-data/
  coding-lanes/
    work/TSK*.json
```

## The set

| phase | count | shape |
|---|---|---|
| `draft` | 4 | title only — three plus one child of an approved task |
| `groomed` | 3 | intent, scope, criteria; one carries a `blocked` overlay |
| `approved` | 3 | criteria covered by steps, every step has `done_when` |
| `executing` | 3 | claimed with a lease, evidence attached; one defers a criterion |
| `code-review` | 3 | steps settled, self round filed, one open finding |
| `remediating` | 3 | external round, `changes-needed`, findings open |
| `needs-human` | 3 | five external rounds exhausted |
| `done` | 5 | clean verdict, no open findings |

Every fixture satisfies the gates of the phase it is in.

## Dependencies

Dependencies run backwards only — a task depends on tasks with lower ids — so
the graph has no cycles and `depends_on` always points at a task that exists.
Three shapes are covered:

- **fan-in** — most tasks wait on two earlier ones; the last `done` task waits
  on three
- **chains** — the `done` tasks form a chain among themselves, and every
  phase waits on the phase before it
- **waiting on a blocked task** — `TSK07` and `TSK08` wait on `TSK05`, which
  carries a `blocked` overlay, so they cannot start until it is unblocked

## Use in tests

```rust
let store = Store::new(repo_root().join("mock-data/coding-lanes/work"));
let task = store.load("TSK07")?;
```

`repo_root()` is `CARGO_MANIFEST_DIR/../..` from a crate under `crates/`.

`crates/core/tests/mock_data.rs` checks the set: it loads, covers every
phase, keeps the gates, and has a sound dependency graph.
